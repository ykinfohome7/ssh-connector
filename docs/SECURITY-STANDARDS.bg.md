# SSH Connector — Приети стандарти за сигурност

Този документ описва приетите стандарти за сигурност в проекта SSH Connector.
Всички участници и AI асистенти (ChatGPT, Claude Code, Codex и др.) трябва да ги спазват.
Английска версия: [SECURITY-STANDARDS.md](SECURITY-STANDARDS.md)

## 1. Алгоритъм за SSH ключове

| Приоритет | Алгоритъм | Кога се ползва |
|---|---|---|
| По подразбиране | **Ed25519** | Всички нови ключове, всички системи, които го поддържат |
| Резервен | **RSA 4096** | Само за стари системи без поддръжка на Ed25519 |
| Забранени | RSA 1024 / 2048, DSA, ECDSA P-256 за нови ключове | Смятат се за слаби или не се препоръчват |

Ed25519 се поддържа от OpenSSH (по подразбиране), GitHub, Debian, Ubuntu, RHEL 8+, Rocky Linux,
Windows OpenSSH и Java 15+.

Генериране на ключ:

```
ssh-keygen -t ed25519 -C "ssh-connector"
```

Резервен вариант:

```
ssh-keygen -t rsa -b 4096 -C "ssh-connector"
```

## 2. Смяна (ротация) на ключовете

- SSH ключовете и данните за достъп се сменят на всеки **40–90 дни**.
- Старите ключове се премахват от `authorized_keys` след смяната.

## 3. Тайни (пароли, ключове, токени)

- Пароли, частни ключове, auth ключове и токени никога не се качват в хранилището.
- Тайните се пазят само в GitHub Secrets или в одобрено хранилище за тайни.
- Тайните никога не се показват в изхода на команди или в логовете.
- Проверката на host key на SSH винаги остава включена.

## 4. Tailscale

- Tailscale (частната мрежа към сървърите) и тунелът на конектора (достъпът от ChatGPT/Claude) са отделни компоненти.
- Командите за Tailscale могат да показват: състояние, версия на Tailscale, свързани устройства и акаунта/потребителското име, с което се свързва конекторът.
- Auth ключовете никога не се показват.
- Генериране на нов auth ключ и отнемане (revoke) на компрометиран ключ се разрешават само с изрично потвърждение от потребителя.
- Ключовете на Tailscale са в собствен фиксиран формат; дължината им не може да се избира.
