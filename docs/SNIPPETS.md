# KSSH snippet library

[Български](SNIPPETS.bg.md)

143 ready-made command templates in 12 categories, documented in English and Bulgarian. **All snippets in this phase are READ_ONLY.** The library is part of the plugin (`plugins/ssh-connector/snippets/*.yaml`, engine `snippet_library.py`) but is **not active on the KSSH server** and adds **no MCP tool** — KSSH 1.4.1 keeps its 60 commands.

> This file is generated by `scripts/gen_snippet_docs.py` — edit the YAML files, not this page.

## Safety model

| Risk | Meaning | Approval | Rendered by the engine |
|---|---|---|---|
| `READ_ONLY` | only reads state, logs or configuration | not required | yes |
| `CHANGE` | changes configuration or state (restart, update, scrub ...) | **required** (`requires_approval: true`) | no (phase 1) |
| `DANGEROUS` | can cause outage or data loss | **required**, plus a second confirmation | no (phase 1) |

* Parameters are typed and validated. Values are inserted only as whole, quoted tokens (POSIX `shlex.quote`, PowerShell single-quoted literal); integers only after a digit check. Placeholders inside quotes are rejected, values may not start with `-`, and `;`, `|`, `$()`, backticks, quotes, spaces and new lines can never reach the shell through a parameter.
* Every READ_ONLY snippet is checked against a deny-list (restart/stop, delete, package changes, network/firewall/VLAN changes, disk/ZFS/Ceph changes, users and passwords, VM/LXC actions, Tailscale/WireGuard changes, output redirection to files, here-documents, arbitrary interpreters). The deny-list is a safety net; every new snippet still needs a human review.
* No secrets in GitHub: SNMPv3 credentials come from `~/.snmp/snmp.conf` on the host, WireGuard private keys are never printed, and the UniFi snippet prints only the inform URL.
* PowerShell snippets are sent as `powershell -NoProfile -NonInteractive -EncodedCommand ...`, pfSense snippets as `/bin/sh -c '...'`, so the login shell does not change quoting.
* The engine only validates, searches and renders. It never opens SSH and never runs anything.

## Privilege levels

| Level | Meaning |
|---|---|
| `user` | normal user account |
| `sudo` | user with sudo rights (read-only commands) |
| `root` | root shell on the host |
| `admin` | local administrator (Windows) / admin shell (pfSense, UniFi) |
| `domain-admin` | Active Directory read rights; some cmdlets need Domain Admins |
| `exchange-admin` | Exchange View-Only Organization Management or higher |

## Parameter types

| Type | Accepted values |
|---|---|
| `int` | digits within the snippet's min..max |
| `port` | 1..65535 |
| `host` | IPv4/IPv6 address or DNS host name |
| `ip` | IPv4/IPv6 address |
| `token` | letters, digits and `. _ @ : -` (no leading `-`), limited length |
| `enum` | one of the listed choices |
| `email` | e-mail address |
| `path` | absolute path, safe characters, no `..` |
| `oid` | numeric OID or `MIB::name` |
| `device` | `/dev/sdX`, `/dev/vdX`, `/dev/nvmeXnY` |
| `iface` | network interface name (max 15) |

## Search and use (today, without the server)

```bash
cd plugins/ssh-connector
python3 snippet_library.py validate
python3 snippet_library.py search --q "disk" --category linux --os debian
python3 snippet_library.py search --q "сертификат" --lang bg      # Bulgarian search works too
python3 snippet_library.py show network.mtu_test --lang en
python3 snippet_library.py render network.mtu_test host=192.0.2.1 size=8972
python3 snippet_library.py export linux.disk_usage linux.memory   # servers.yaml 'snippets:' block
```

Search matches every word against the id, the EN and BG names and descriptions, the category, the operating systems and tags; filters: `--category`, `--os`, `--risk`, `--tag`.

## Calling snippets through MCP

**Works with KSSH 1.4.1 now (after approval, phase 2):** parameter-less READ_ONLY snippets can be exported with `snippet_library.py export ...` into the `snippets:` section of `servers.yaml`; they are then listed by `list_snippets` and run by the existing `run_snippet(server, name)` — no code change and still 60 MCP commands.

**Proposal for a later version (needs separate approval, would make 63 commands):**

| Tool | Purpose |
|---|---|
| `snippet_search(query, category, os, risk, lang)` | search the library (EN/BG) |
| `snippet_show(id, lang)` | full description, parameters, example, risk |
| `snippet_run(server, id, params)` | validate parameters, render and run through the existing SSH layer; READ_ONLY only, `sudo` only when the snippet says so, timeout from the snippet, every call written to `history` as `snippet:<id>` |

`snippet_run` would refuse CHANGE/DANGEROUS snippets until an approval flow exists (explicit `approve=true` from the user plus an audit entry), and would check that the target server's `os` matches the snippet's `os` list.
